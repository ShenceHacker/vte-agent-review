# VTE医生评审工作台

网站独立于模型运行服务。前端为原生HTML/CSS/JavaScript，后端为Python标准库HTTP服务、SQLite；FE Nginx提供HTTPS。病例原始Word、编号与本地路径不放进网站静态目录。医生仅通过服务端白名单邮箱和邮件验证码登录。

## 评审流程

1. 登录后按病例队列依次查看每个时间点：中文病例文字、检查图、当前D建议及检索依据。
2. R2七项1–5分评分；NA为不适用，NE为评审材料不足以判断，分别写理由。1–3分逐项说明欠缺，需修改时填写一句话最小必要修改。另选总体可接受性及是否存在安全关键错误。
3. 草稿自动存入服务器。提交后原始评分锁定，本次医生处方开放，下一时间点解锁。此前时间点可以回看，未来资料和他人评分不开放。
4. 可导出本人CSV。重复导入同一批结果不会清空评分；发布后的病例回答与评分标准绑定哈希，不能悄悄替换。

## 评分依据及版本

当前标准为 `VTE-R2-2026-10-13`，状态为“研究草案，待医生试评校准”。用户2026-10-13明确要求直接替换R1、不保留历史入口；部署时确认无任何医生评分，未把旧评分重标为R2。过期页面提交缺失版本或R1版本时返回409，必须刷新。

七个维度及完整五级锚点在 `vte_review/rating_rubric.py` 中维护，网页“评分说明”同步展示：诊断与抗凝决策合理性、药物选择与个体化给药、疗程时间线与动态调整、病例事实忠实度、安全风险识别与处置、证据适用性与不确定性处理、完整性与临床可执行性。表单默认收起详细锚点，只在相关选择后展开逐项原因或安全事件，避免长表说明占满屏幕。

安全关键错误记录唯一事件ID、五类错误类别、问题原文或遗漏、病例证据、适用临床规则、潜在后果（出血/复发进展/延误处置/其他）和轻/中/重严重度；同一事件可关联多个维度。确认关键错误不能同时选择“无需实质修改”或“小幅修改后可用”。重大错误与D5高分/NA/NE不一致时必须解释，导出标记待仲裁；无法判断单独说明，不强迫虚构错误事件。

CSV仅导出本人已提交记录，包含R2版本、回答哈希、逐项分数与说明、结构化安全事件JSON、待仲裁状态、总体判断及最小必要修改；NA/NE保留原值，不计0分。草稿及已提交回看均保留完整记录。

参考DKD的分维度五级评价与独立安全审计、Med-PaLM对正确性/伤害/有用性的区分、QUEST的情境化独立评审与仲裁，以及PDSQI-9的摘要事实忠实度与遗漏。网页分别说明借鉴范围，不声称继承已验证量表的测量效度。

- DKD：https://www.nature.com/articles/s41746-026-03035-0
- Med-PaLM：https://www.nature.com/articles/s41586-023-06291-2
- QUEST：https://www.nature.com/articles/s41746-024-01258-7
- PDSQI-9：https://pmc.ncbi.nlm.nih.gov/articles/PMC12089781/

网页手册包含VTE专用细则、试评要求及研究指标的定义/分母。当前站点只评价最终建议，没有首稿配对评分与仲裁真值，不能从该表直接计算审核纠错率或修订新增错误率。未自动生成临床分数或研究结论。

正式研究前建议至少两名相关专业医生对同一小批病例独立试评，讨论分歧，再冻结正式版本。安全关键错误以潜在临床风险单独统计，不能被其他维度高分抵消。不同处方不自动等于错误；需要结合病情、适用地区说明书及医生调整理由。

## 语言与研究记录

原10例保留英文模型结果，仅增加忠实中文译文，不能借翻译修正原有错误。译文检查结构、数值和来源哈希，网页保留英文原文供核对；自动检查不能替代医生核对语义。新增病例直接以中文输出。导出及审计应区分翻译展示与中文原生生成，不能忽略这一差异。

多数随访没有独立医生诊断标签。原医生处方为比较记录，不自动作为安全性真值；报告中保留的影像结论属于模型输入，不能据此声称独立阅片诊断准确率。

## 数据与运行

- 统一本地目录：`data/vte_dataset/`（Git忽略）。`private/`保存原件和导入来源，`manifest.json`记录文件/临床内容指纹与重复关系；原件不覆盖。
- `results/evaluation-20261009/`复用前10例结果；`processing/sol-20261012/`仅处理新20例；`translations/`保存旧结果中文译文和源哈希。
- `private/history/evaluation-20261009/`保存旧10例完整运行归档，导出脚本优先从此目录读取；原`runs`记录保留。当前批次共30例、107个时间点，全部有中文报告。
- `portal/bundle.json`及`portal/assets/`是允许上传的脱敏病例包；原始Word、私有映射、模型API密钥不会打入发布包。
- `scripts/export_rating_bundle.py`仅导出有最终建议的节点，技术失败草稿不当作完成建议；缺中文版本的节点暂不发布。服务器还会防止跨时间点访问。
- 医生评分独立存服务器`/var/lib/vte-review/ratings.sqlite3`，不由病例导出脚本覆盖；发布前以SQLite backup API做本机备份。

完整导出后运行`python scripts/verify_rating_bundle.py --previous-archive runs/rating-portal-release-b.tar.gz`，核对每个时间点的来源、中文报告与原运行对应关系、已发布回答不可变，以及全部引用图片的哈希。核验输出写入本地忽略目录`data/vte_dataset/final-verification.json`。该命令只验证数据完整性，不给真实病例评分。网站仅在核对具体包后手动更新，未启用持续后台上传。

## 运维

`VTE_REVIEWERS`设置白名单，`VTE_PORTAL_SECRET`用于验证码及会话摘要，`VTE_SMTP_CONFIG`指向仅服务可读的邮件配置。不得把这些值提交Git。验证码10分钟、单次5次试错，会话8小时；接口校验Origin、CSRF、Host和权限，病例响应禁止缓存。

本站复用FE现有邮箱发件配置，部署仅验证SMTP连接/认证，不主动向医生发送测试消息。医生点击发送验证码后才发送登录邮件。

SQL导出按患者、时间点、医生、回答哈希和rubric版本留痕。多时间点统计需考虑患者内相关性；NA和NE不是0分。默认不生成一个掩盖安全错误的总分，也不自动给医生打分。

R2代码替换脚本为 `scripts/deploy_rating_r2_remote.py`：只上传程序，停评审服务后再次确认没有医生评分或意见，SQLite备份，切换版本并检查健康；仅自动计时的空R1草稿重置为R2空草稿；失败恢复原服务。病例、回答及图片保持原样，脚本不读取或打印邮件密钥。后续已有评分内容时不能复用此无评分输入前提的脚本直接换规则。
